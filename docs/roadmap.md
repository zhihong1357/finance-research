# 落地顺序

## 当前状态

**Phase 1 · 骨架** 已完成，下一步是 **Phase 2 · 数据平台**（2026-11-13）。Phase 0.5 的期权链录制继续运行。

- Phase 0 已完成：所有者确认骨架按文艺复兴的方向搭建（决策 0001），仓库保持公开到 Phase 4 结束（0002），第一个研究宇宙是加密永续合约（0007）。
- Phase 0.5：原始期权链的保存已提交，见 orderflow 仓库的拉取请求 #5。
- Phase 1 已完成（2026-11-13）：细线 H-0001 已入账（T-000001），持续集成每次都从空白状态重现它。
- Phase 2 数据平台：2.0 开工核实与拆分进行中。存储用 Hugging Face 私有数据集（0003 已采纳）。
- 单一模型（0006）待所有者决定，Phase 4 开始前需要。

## 排序原则

1. **事后补不回来的先做。** 试验记录、数据的时间语义、无法重新获取的原始数据，错过了无法重来。算法和模型随时可以加。
2. **模型和成本先于信号。** 信号的价值只能在扣除成本后的整体组合里评估，所以统一模型和模拟器要在第一个信号研究之前就位。
3. **达标才进下一阶段。** 每个阶段都有验收标准，写成可以检查的事实。
4. **每个阶段结束时，系统都能完整跑通一遍。** 先做一条贯穿各层的细线，再逐层加宽。
5. **不赶时间。** 本文不给日期，只给顺序和标准。

|---|---|---|

## Phase 0.5 · 止损：保存无法重新获取的数据

这是整份计划里唯一有时间压力的事。

**问题。** 美股期权链（CBOE）和 Deribit 期权快照都只提供当前状态，当天不存，以后就找不回。加密永续合约的逐笔成交有官方的长期归档，不在此列。

**做法。** 本仓库在 Phase 2 之前没有数据存储，而且是公开仓库，不能存放第三方数据。所以过渡期借用一个已经在运行、并且是私有的定时任务：在旧系统的录制步骤里加一步，把 SPX、SPY、QQQ、IBIT 四个标的的原始期权链压缩保存，实测合计约 3.5 MB/天。Deribit 期权快照已经在另一个旧仓库里每天保存（自 2026-10-26 起）。Phase 2 的数据平台建成后接管这两项录制，并导入已存的文件。

**验收。** 每个美股交易日，四个标的的原始文件都存在且能正常解压读取。

## Phase 1 · 骨架

**目标。** 建成治理层和内核库的最小可用版本，使[总纲](charter.md)里"事后补不回来的三样东西"从第一天起就被正确处理。

**步骤。** 每一步是一次独立的、可审查的拉取请求。

| 步骤 | 内容 |
|---|---|
| 1.1 工程底座 | 目录结构、依赖锁定、代码风格与类型检查、测试框架、持续集成 |
| 1.2 时间与标识 | 带时区的时间类型、交易日历（包括全天交易的市场）、品种标识方案（同一品种在不同交易所的代码） |
| 1.3 溯源 | 内容指纹、运行清单、配置指纹、结果指纹 |
| 1.4 注册表 | 五类文件的格式定义、校验命令、"只追加"检查 |
| 1.5 时点查询 | 在仓库内的小型测试数据集上实现，包含时钟上限、三段边界和金库令牌 |
| 1.6 贯穿各层的细线 | 合成数据（由代码按固定种子生成，模仿一个真实数据源的格式，带三个时间，含一次修订）→ 原始层 → 规范层 → 时点查询 → 一个登记的示例假说 → 一次运行 → 账本记录 → 标准报告 |

**验收。**

- 持续集成全部通过。
- 一条命令从空白状态重现 1.6 的报告，结果指纹与仓库里记录的一致。
- 故意写一段前视代码，测试失败。
- 故意删掉一条账本记录，持续集成失败。
- 故意越过金库边界查询，程序报错并留下记录。

**不做。** 不接入远程存储，不写真实的采集器，不做任何真实研究。细线用合成数据，所以 Phase 1 不涉及任何第三方数据的存放问题。

## Phase 2 · 数据平台

**目标。** 让数据持续、自动、可追溯地流入，并在出问题时有人知道。

**产出。**

| 类别 | 内容 |
|---|---|
| 存储 | 后端见[决策 0003](decisions/0003-data-storage.md) |
| U1 加密永续合约 | 归档清单：Binance 和 Bybit 的全部 USDT 永续合约（含已下架），每个文件的地址和官方校验和。加工：在 GitHub Actions 里按需下载、校验，把逐笔成交加工成 1 分钟数据（含主动买入量、主动卖出量、成交笔数、成交均价）。另含资金费率、持仓量、标记价格 |
| 录制 | 接管 Phase 0.5 的期权链录制；Deribit 期权与期货；各交易所资金费率和基差的定时快照 |
| 宏观与利率 | 宏观指标的历史公布版本（取自原始发布机构和费城联储实时数据集；FRED 的条款禁止存档，见[架构](architecture.md) 7.5）、纽约联储 SOFR、CFTC 持仓报告、VIX 历史 |
| 数据源目录 | 每个数据源的地址、时间语义、限流、使用条款摘要、是否可重新下载、已知问题 |
| 质量检查 | 格式、取值范围、新鲜度；同一品种在不同交易所之间的价格相互核对 |
| 监控 | 任何数据源中断时通知 |
| 数据画像 | U1 的品种数量随时间的变化、流动性分布、有效广度估计 |

**验收。**

- U1 全宇宙（含已下架品种）的 1 分钟数据可以按时点查询，加工所用的原始文件全部通过官方校验和。
- 录制类数据源连续 14 天自动入库，期间没有人工干预。
- 任何一个数据源中断，24 小时内收到通知。
- 删除规范层之后，能由原始层和归档清单完整重建，内容指纹一致。
- 数据画像给出 U1 的有效广度估计。如果不足 30 个独立下注，按[决策 0007](decisions/0007-breadth-first-universe.md) 重新考虑研究宇宙。

**步骤。** 排序按"事后补不回来的先做"：存储是一切的前提；监控先于录制，没有监控的录制会悄悄停掉；录制的数据错过就没有了，所以紧接着做；可以随时重新下载的归档和加工放在后面。

| 步骤 | 内容 | 验收 |
|---|---|---|
| 2.0 开工核实与拆分 | 核实架构 7.4 原列的问题；拆分本阶段的步骤 | 本表；架构 7.3 至 7.5 |
| 2.1 存储 | 统一的存储接口：本地实现供测试，Hugging Face 实现供运行。原始层和规范层改走这个接口；按年、月分层，攒批提交。所有者注册账户、把令牌存进 GitHub Secrets | 在 GitHub Actions 里写入、读回、核对指纹；实测的速度和失败率写进架构 7.3；测试仍不联网 |
| 2.2 定时任务与监控 | 每个数据源一个独立的定时任务，一个失败不影响其他；新鲜度检查；数据中断时自动开一个 GitHub issue（所有者会收到邮件）；防止定时任务在 60 天无活动后被停用 | 故意让一个模拟数据源中断，24 小时内收到通知，其他数据源照常入库；保活措施经过实测 |
| 2.3 录制 | 接管旧仓库的录制：Deribit 期权与期货快照、各交易所资金费率和基差快照；美股期权链按所有者对 Cboe 条款的决定处理。旧仓库已录的数据导入原始层 | 连续 14 天自动入库，期间没有人工干预；导入的旧数据与原文件指纹一致 |
| 2.4 归档清单 | Binance 和 Bybit 的全部 USDT 永续合约（含已下架）：每个文件的地址、大小、校验和。Binance 用官方 SHA-256；Bybit 没有官方校验和，首次下载时自算 SHA-256 并记下 ETag，数据源目录注明保证较弱 | 清单覆盖两家的全部品种和日期；抽样重新下载，与清单一致 |
| 2.5 U1 加工 | 逐笔成交加工成 1 分钟数据（主动买入量、主动卖出量、成交笔数、成交均价）；资金费率、持仓量、标记价格 | 全宇宙 1 分钟数据可以按时点查询；删除规范层后由归档清单重建，内容指纹一致 |
| 2.6 宏观与利率 | 宏观指标的历史公布版本、纽约联储 SOFR、CFTC 持仓报告、VIX 历史；先核实各自的条款 | 每个序列带三个时间，修订前的值可以查到 |
| 2.7 质量检查 | 格式、取值范围、新鲜度；同一品种在不同交易所之间的价格相互核对 | 故意植入的每类错误都被检出 |
| 2.8 数据画像 | U1 的品种数量随时间的变化、流动性分布、有效广度估计 | 给出有效广度估计；按[决策 0008](decisions/0008-derived-results.md)，具体数字存在私有数据集里 |

规模估计：Bybit 的 BTCUSDT 一天的逐笔成交约 65 MB，上千个品种、多年的原始文件远超 100 GB 的额度。所以两家交易所的逐笔成交都按架构 2.2 的例外处理：原始层只记地址和校验和，不存字节，需要时重新下载。

## Phase 3 · 推断工具箱与元研究

**目标。** 在用这套系统研究市场之前，先研究这套系统本身：它会不会把噪声当成发现，能不能找到真实存在的效应。

**产出。**

- 统计工具箱：多重检验校正、平稳自助法、带清洗和禁区的交叉验证、功效计算、折损夏普、回测过拟合概率。
- 噪声工厂：生成没有任何优势的合成数据，同时保留真实数据的厚尾、波动聚集和品种之间的相关结构。
- 植入效应的合成数据：在噪声里埋入已知大小的效应。
- 阳性对照：在真实数据上复现被文献反复确认的效应。候选是股指的隐含波动率长期高于实现波动率，以及加密市场横截面的动量效应（Liu, Tsyvinski & Wu, 2022）。

**验收。**

- 在纯噪声上，整条流程（从探索到结论）的误报率不高于名义水平。
- 给出不同效应大小和数据长度下的检出率曲线。
- 阳性对照复现成功。
- [科研规程](protocol.md)第 5 节的阈值据此定稿。

## Phase 4 · 统一模型与模拟器

**目标。** 在第一个真实信号出现之前，建好接收信号、合成组合、扣除成本、评估边际贡献的全部机器（[架构](architecture.md)第 5 节）。

**产出。**

- 信号接口。
- 组合模型第一版：换算到预期收益单位，按收缩后的权重线性相加。
- 组合构建器：约束、带收缩的风险模型、按波动率调整总仓位、回撤规则。
- 成本模型：各交易所手续费、由数据估计的买卖价差、资金费率、随参与率上升的冲击成本。
- 事件驱动的模拟器，与将来的模拟盘共用代码。
- 边际贡献检验和容量估计。

**验收。**

- 在植入了若干已知强度信号的合成市场上，模型能找回真信号；边际贡献检验能把真信号和纯噪声信号分开，误报率符合 Phase 3 量出的水平。
- 一组手算的场景，逐笔结果一致。
- 成本为零、正常、加倍三种情形的结果都能一键得到。
- 信号在接口层面拿不到未来数据（沿用 Phase 1 的测试）。

## Phase 5 · 信号研究

**目标。** 按规程开展真正的研究，通过准入的信号进入模型。

**顺序。**

| 顺序 | 项目 | 排在这里的理由 |
|---|---|---|
| 5.1 | P1 短周期价格与订单流 | 原料最完整（逐笔成交、全宇宙、多年历史），广度最大 |
| 5.2 | P2 衍生品定位 | 资金费率、持仓量的历史同样完整 |
| 5.3 | P3 跨市场关系 | 需要多个交易所的数据对齐，依赖 5.1 的数据加工 |
| 5.4 | P4 期权流 | 依赖录制数据的积累，预计 2027 年中以后才有足够样本 |
| 5.5 | P5 宏观与流动性 | 作为风险缩放进入组合构建器 |
| 5.6 | U2 美股 ETF 与期权 | 第二个研究宇宙 |

**验收。** 每个项目至少有一个假说走完整个生命周期并入库。结论是"支持"还是"不支持"都算完成。

## Phase 6 · 资金配置

**目标。** 决定所有者的资金怎样在统一模型和低成本的基准组合之间分配。

**产出。**

- 所有者的目标与约束文件，包括能承受的最大回撤。
- 基准组合：低成本、分散。模型要先赢过它，才值得分配资金。
- 配置规则：只有证据等级 E4 以上的模型版本参与；配置比例按分数凯利，系数由优势估计的不确定度决定。
- 历史压力情景的检验。

**验收。** 给定模型的前向记录和所有者的约束，系统输出配置建议及其依据，并通过压力情景检验。

---

## Phase 7 · 模拟盘

**目标。** 在不动用资金的情况下，取得前向证据。

**产出。** 前向运行的模拟盘，带预先登记的停止规则。

**验收。** 运行长度达到事先算好的最短长度，实际表现落在预期分布之内（证据等级 E5）。

## Phase 8 · 实盘闸门

不在当前范围。进入条件是证据等级 E5、所有者的明确决定，以及每个用到的数据源的条款都允许把由它得出的模型用于实盘（[决策 0008](decisions/0008-derived-results.md)）。Binance 公开数据站目前明确不允许。
