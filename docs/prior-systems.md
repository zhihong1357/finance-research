# 前三个系统的资产与教训

新系统不是从零开始。`market-weather-bot`、`fakeout-backtest`、`orderflow` 三个仓库留下了可以直接继承的代码和数据，也留下了几条用真实结果换来的教训。本文根据 2026-11-13 对三个仓库的检查写成。其中两个是私有仓库，所以这里只写到能力和教训的层面，不写策略规则和回测数字。

## 1. 可以继承的资产

### market-weather-bot

| 资产 | 说明 |
|---|---|
| 二十多个免费数据源的接入代码 | 多家交易所的现货和永续、Deribit 的 DVOL 与期权、FRED、Yahoo、CFTC 持仓、CME 基差、稳定币供应、清算数据、新闻情绪等 |
| 失败处理的经验 | 每个数据源独立失败、多源取中位数、失败汇总进报告 |
| Telegram 通知 | 状态变化提醒和每日早报 |

六种"市场天气"的分类规则不继承。它的阈值是手工设定的，没有经过检验，在新系统里属于待检验的假说。

### fakeout-backtest

| 资产 | 说明 |
|---|---|
| Deribit 全量期权的每日原始快照 | BTC 和 ETH，自 2026-10-26 起。这是三个仓库里最有价值的东西，因为它无法重新获取 |
| Binance 公开数据站的接入 | K 线、资金费率、持仓量、多空比 |
| 手册里的门槛规则 | 交易笔数不少于 100、去掉最赚的 2 笔后仍为正、前 70% 和后 30% 时间段都为正、赚钱的年份过半。这些规则被[科研规程](protocol.md)沿用 |

### orderflow

| 资产 | 说明 |
|---|---|
| 事件驱动的回测引擎 | 成交规则保守且明确：市价单下一根开盘价成交，限价单被穿过才成交，计入手续费和滑点 |
| "不前视"的工程约定 | K 线在收盘后才存在，摆动点在右侧 K 线收完后才存在 |
| 指标库 | 成交量分布、摆动点、ATR、FVG |
| 期权计算 | Black-76、GEX、零 Gamma 翻转价、状态分类的滞后带 |
| 模拟盘与通知 | 每 2 小时运行，与回测共用同一套成交逻辑 |
| 763 个测试 | 多数带手算的期望值 |
| `lab` 科研层 | 防过拟合统计、美股期权流、空间价差、宏观共振检验，以及每 2 小时的自动录制 |

## 2. 已有的结果

这些结果是新系统的起点，也是[总纲](charter.md)核心判断的依据。

| 研究 | 结果 | 来源 |
|---|---|---|
| 旧策略按手册自己设定的门槛复核 | 未能全部通过；换到其他品种后表现明显变差。具体数字留在私有仓库 | `fakeout-backtest` |
| 期权平价，BTC 和 ETH，22 个到期日 | 扣费后缺口为 −15 至 −39 bps，没有套利空间 | `orderflow/docs/lab.md` |
| 期货基差 | BTC 远月扣费后年化约 5%，同期 3 个月美债约 4.06% | 同上 |
| 四层水晶球共振，2001 至 2026 | 四层同时亮灯从未出现；三层亮灯只有 6 个独立事件 | 同上 |

第一行值得多说一句。利润集中在极少数几笔交易上，同样的规则换一个品种就不成立，这是"在一个市场上调出来的规则"的典型表现。

## 3. 教训

| 教训 | 出处 | 新系统的对策 |
|---|---|---|
| 参数曾经对着个别交易来调整 | `orderflow` 的策略说明 | 检验方案预注册；参数扰动是必检项 |
| 参数对比没有记录试了多少组 | `orderflow` 的 Sweep 工作流 | 试验账本自动记账，折损按账本计算 |
| 只存了算出来的指标，没存原始数据 | `orderflow` 的 CBOE 期权链录制 | 原始层只增不改；[落地顺序](roadmap.md)的 Phase 0.5 |
| 状态分类的阈值没有依据 | `market-weather-bot` 的六种天气 | 阈值本身是假说，要经过检验 |
| 一个策略只在一个品种上成立 | `fakeout-backtest` | 跨市场复现是证据等级 E3 的必要条件 |
| 公开仓库里出现了账户标识 | `market-weather-bot` 提交回仓库的状态文件 | 公开仓库不放任何账户标识，一律走加密的 Secrets |

`orderflow` 里也有做对的地方，新系统原样保留：它的数据源调研文档明确写着 GEX 在加密市场的预测力尚未被证实，并要求 GEX 必须在样本外赢过免费的替代指标才能参与决策。

## 4. 新旧系统的根本区别

| | 旧系统 | 新系统 |
|---|---|---|
| 起点 | 一个策略 | 一个机制 |
| 流程 | 回测 → 调参 → 再回测 | 登记 → 检验一次 → 记账 |
| 成功的定义 | 回测曲线好看 | 结论的证据等级提高，或者假说被干净地否定 |
| 数据 | 用到什么抓什么 | 先存原始数据，按"何时可知"查询 |
| 失败的尝试 | 被覆盖 | 永久保留 |

## 5. 实测得到的环境知识

这些是在三个仓库和 2026-11-12 的实测中确认的事实，新系统的采集器直接采用。

- GitHub 的服务器在美国。Binance 的主接口拒绝美国 IP，公开行情改用 `data-api.binance.vision`，历史文件改用 `data.binance.vision`。
- Binance 公开数据站当月的资金费率要到下个月才发布。
- CBOE 延迟期权链的 `timestamp` 字段是 UTC 时间。
- CBOE 期权链里深度实值合约的隐含波动率是无效值，计算前要过滤。
- Yahoo 的行情接口用 `range=max` 会把日线降采样成月线，要改用起止时间参数。
- FRED 的 CSV 接口一次请求多个序列会超时，要一次一个。
- Deribit 的期权和期货在 08:00 UTC 到期。
- Deribit 只覆盖约一半的 BTC 期权持仓，另一半在美股的 IBIT 期权上。
- OKX 的资金费率周期要从接口返回的两个时间戳相减得到，不能假设是 8 小时。Hyperliquid 是每小时结算。
