# 旧系统中可取用的部分

本系统是全新的设计，不继承旧系统的结构和策略。`market-weather-bot`、`fakeout-backtest`、`orderflow` 三个旧仓库里，只有以下几类东西值得取用。取用时一律按本仓库的约定重写，并配上测试。

## 1. 数据

唯一不可替代的是**已经录下来、无法重新获取的数据**：

| 数据 | 起始 | 所在 |
|---|---|---|
| Deribit 全量期权每日快照（BTC、ETH） | 2026-10-26 | `fakeout-backtest` |
| Deribit GEX 快照 | 2026-10 | `orderflow` 的 `gex-data` 分支 |
| 基差、资金费率、期权平价、美股期权流指标的定时快照 | 2026-11-12 | `orderflow` 的 `lab-data` 分支 |

Phase 2 的数据平台建成后，这些文件导入原始层，旧仓库的录制任务停用。

## 2. 可参考的实现

| 内容 | 所在 | 用在 |
|---|---|---|
| 二十多个免费数据源的接入方式，以及单个数据源失败不影响其他数据源的写法 | `market-weather-bot` | Phase 2 采集器 |
| Black-76 定价与 Gamma、GEX、零 Gamma 翻转价的计算 | `orderflow` | P4 期权流 |
| 保守的成交规则：市价单按下一个可成交价格成交，限价单必须被穿过 | `orderflow` | Phase 4 模拟器 |
| 防过拟合统计（概率夏普、折损夏普、回测过拟合概率、分块自助法） | `orderflow` 的 `lab/stats` | Phase 3 工具箱 |

## 3. 教训

| 教训 | 本系统的对策 |
|---|---|
| 参数曾经对着个别交易来调整 | 检验方案预注册；参数扰动是必检项 |
| 参数对比没有记录试了多少组 | 试验账本自动记账，折损按账本计算 |
| 只存了算出来的指标，没存原始数据 | 原始层只增不改；Phase 0.5 |
| 一个策略只在一个品种上成立 | 结论登记适用范围；跨宇宙复现是证据等级 E3 的条件 |
| 公开仓库里出现过账户标识 | 公开仓库不放任何账户标识，一律走加密的 Secrets |

## 4. 实测得到的环境知识

在旧系统和 2026-11-12、11-13 的实测中确认的事实，本系统的采集器直接采用：

- GitHub 的服务器在美国。Binance 的主接口拒绝美国 IP，公开行情改用 `data-api.binance.vision`，历史文件改用 `data.binance.vision`。
- Binance 公开数据站当月的资金费率要到下个月才发布。
- CBOE 延迟期权链的 `timestamp` 字段是 UTC 时间。
- CBOE 期权链里深度实值合约的隐含波动率是无效值，计算前要过滤。
- Yahoo 的行情接口用 `range=max` 会把日线降采样成月线，要改用起止时间参数。
- FRED 的 CSV 接口一次请求多个序列会超时，要一次一个。
- Deribit 的期权和期货在 08:00 UTC 到期。
- Deribit 只覆盖约一半的 BTC 期权持仓，另一半在美股的 IBIT 期权上。
- OKX 的资金费率周期要从接口返回的两个时间戳相减得到，不能假设是 8 小时。Hyperliquid 每小时结算。
