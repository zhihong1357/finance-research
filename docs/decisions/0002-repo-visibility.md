# 0002 · 仓库暂时保持公开

**状态：** 提议（2026-11-13，第二版加入文艺复兴方向的考虑）

## 背景

`finance-research` 创建时是公开仓库。公开和私有各有代价：

| | 公开 | 私有 |
|---|---|---|
| GitHub Actions | 标准运行器免费，不限分钟 | 免费账户每月 2,000 分钟，与 `orderflow`、`fakeout-backtest` 共用 |
| 研究内容 | 任何人可见，包括假说和试验账本 | 仅自己可见 |
| 第三方数据 | 不能存放，公开转载可能违反数据源的使用条款 | 个人存档的风险较低 |
| 历史 | 一旦公开过，就应当假定已被复制 | — |

本系统以文艺复兴为方向标杆，这带来一个新的考虑：文艺复兴以极度保密著称，员工签终身保密协议。但它保密的是具体的信号和模型参数，不是方法论。它的方法论（单一模型、广度、数据为本、只招科学家）早已通过书籍和报道公开，本仓库第 0 至 4 阶段的内容属于这一类。

## 决定

Phase 1 至 Phase 4 保持公开。这几个阶段只产出方法、工具和对工具本身的检验，没有需要保密的内容，而元研究的大量模拟正好用得上不限量的运行时间。

Phase 5 开始前重新决定。届时有三个选项：整体转为私有；保持公开；拆成公开的工具仓库和私有的研究仓库。

按文艺复兴的方向，倾向于第三个选项：

| 放在公开的本仓库 | 放在新建的私有仓库 |
|---|---|
| 内核库、数据加工、模拟器、统计工具、规程 | 假说卡、信号的实现、组合模型的参数、试验账本、研究报告 |

这样分的另一个好处是运行时间：数据加工最耗运行时间（全宇宙逐笔成交的下载和加工），它留在公开仓库里不受分钟数限制；信号研究在已加工好的数据上运行，耗时少得多，私有仓库的额度够用。

公开仓库的运行日志对外可见，所以数据加工任务不在日志里打印任何数据内容。

无论公开与否，以下内容永远不进入这个仓库：

- 第三方的原始数据。
- 密钥和令牌，一律使用 GitHub 的加密 Secrets。
- 账户标识和个人财务信息。

## 理由

- 公开转私有只需要在设置里点一下，这个决定可以推迟。
- 推迟到 Phase 5 时，对"有没有值得保密的东西"会有实际的了解。
- 第 0 至 4 阶段只有方法和工具，没有任何信号，公开不泄露竞争优势。

## 代价

- Phase 1 至 4 的全部设计和代码对外可见。
- 需要始终留意不把上面三类内容提交进来。

## 何时重新考虑

Phase 5 开始前；或者任何时候需要在仓库里存放不宜公开的内容。
