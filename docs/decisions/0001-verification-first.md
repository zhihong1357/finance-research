# 0001 · 以检验体系为骨架

**状态：** 已采纳（2026-11-13）。所有者确认：骨架按文艺复兴的方向搭建。

## 背景

系统要从"骨架"开始建。骨架可以有三种理解：数据管道、回测引擎，或者检验体系（规程、试验账本、时点数据语义、溯源）。

## 决定

骨架是检验体系。Phase 1 只建治理层和内核库里与检验有关的部分，用一条贯穿各层的细线验证它们能协同工作。数据平台和回测引擎放在之后。

## 理由

- 试验次数、数据的可得时间、未被看过的数据，这三样事后补不回来。数据管道和回测引擎随时可以重写。
- 文艺复兴的经验同样指向这里：它的方法核心是只认检验、不认故事，以及把现实细节全部做进模型（见[以文艺复兴为参照](../renaissance.md)）。
- AI 助手使试验成本接近零。没有自动记账，试验次数会在不知不觉中膨胀。

## 代价

- Phase 1 结束时还看不到任何关于市场的新结论。
- 规程会让每项研究变慢。

## 何时重新考虑

Phase 3 的元研究如果显示，规程在纯噪声上的误报率并不比不用规程时低，就说明这套体系没有起作用，需要重新设计。
