# 0022 · 等待期间新加的模块可以修改：只限录制流程加载不到的那些

**状态：** 已采纳（2026-11-18）。所有者在会话中选了"现在修"。本条是[决策 0017](0017-phase-3-during-phase-2-acceptance.md) 第 2 条下的一个例外；0017 的其余约束不变。

## 背景

决策 0017、0020 之后，Phase 3、4 在等待期间新加了一批模块：统计工具（`stats/` 下的五个新文件）、判定函数（`verdict.py`）、信号接口（`model/`、`signals/`）、成本模型和模拟器（`sim/`），以及两份配置（`config/costs.toml`、`config/simulator.toml`）。

按"不审查自己的结论"，另开了一个会话独立审查这批代码。提出的问题我逐个复现过，确实存在的有这些：

| 问题 | 后果 |
|---|---|
| 研究或信号代码能拿到手里那扇门的内部表格，再配一个新时钟，自己造一扇不受时钟限制的门 | 能读到决策时刻之后的数据，清单里不留痕迹 |
| 折损夏普的"运气基准"在有效试验次数刚过 1 时变成负数 | 试验次数多了，门槛反而比不打折还松 |
| 限价单的到期只对照 K 线的开始时刻 | 一根跨过到期时刻的 K 线也能让它成交，而那根 K 线里价格是在到期之前还是之后穿过的，数据说不清 |
| 冲击成本按每张订单单独算 | 一笔 10 万美元的单子拆成 100 张，冲击成本只剩十分之一（1,264.91 → 126.49），模拟结果被高估 |
| 测试里写着"压力情形从不比保守情形好" | 一般并不成立：亏钱的限价单只成交一半，亏得反而少 |
| 最后一根 K 线结束时刻的资金费不进权益曲线 | 权益曲线的终点与现金和持仓对不上 |
| 常数收益（例如全是 0.1）没被识别 | 浮点舍入让标准差不为零，算出一个巨大的夏普 |
| 模拟器不检查 NaN 价格、负的限价、错位的 K 线等输入 | 错误的输入悄悄算出错误的结果 |
| 假说卡允许的最严阈值（折损夏普 ≥ 1、过拟合概率 ≤ 0）判定函数不接受 | 一张合规的卡会让判定直接报错 |
| Wilson 区间的端点、功效计算的最少样本、均值的溢出 | 边界情况下结果不对或报错类型不对 |

另有一处是决策 0018 的模拟次数前后不一致，单独写在[决策 0023](0023-meta-research-run-counts.md)。

这些模块还没被用来做任何真实研究，所以错误没有造成后果。但不修，下一步的元研究和模拟器验收都建在它们上面。

修它们要改已经合并的文件，而 0017 第 2 条字面上是"只新增文件，不改 `src/`、`config/`、`.github/workflows/` 里已有的文件"。

## 这一条约束防的是什么

0017 第 2 条的理由是：所有定时工作流从 `main` 运行同一个 `finresearch` 包，改了已有的模块，下一次采集就跑新代码，14 天观察就不再是同一套系统。

这个理由只对录制和加工流程会加载的文件成立。等待期间新加的这批文件，录制流程一个都不加载：

- 工作流只调用命令行入口（`src/finresearch/cli.py`）。
- 导入命令行入口之后，这批模块一个都没有被加载（实测，见下面的测试）。
- 其他已有模块都不导入它们，包括函数体里的延迟导入。
- 两份配置只由这批模块读取，工作流里也不出现它们的名字。

## 决定

在 0017 第 2 条下加一个例外：**等待期间新加、录制流程加载不到的模块和配置，可以修改。** 条件：

1. **范围由测试划定。** 只限 `tests/test_wait_isolation.py` 里列出的模块和两份配置。这份测试检查上面四点；它不过，拉取请求就不能合并。新加的模块进了这些包，必须列进去，同样受检查。
2. **录制和加工用到的已有文件照旧不动。** 0017 的第 1、3、4、5 条不变。
3. **修改照常走拉取请求**，每个错误先写一个会失败的测试，再改代码。
4. **随 0017 一起失效。** Phase 2 两项验收通过后，0017 的约束解除，本条也失效；命令行入口那时会接上这些模块，`tests/test_wait_isolation.py` 随之删掉。

## 为什么不影响 Phase 2 的验收

- **2.3 的 14 天观察**看的是录制流程：采集、推送、补跑、质量检查。它们跑的是命令行入口和它加载的模块，这些文件一个字没变。
- **2.10 的重建核对**比的是内容指纹。算指纹的代码（`data/table.py`）没动，依赖的版本没动（`uv.lock` 不变）。

## 留到 Phase 2 验收之后的部分

- 假说卡格式（`registry/models.py`，命令行入口会加载）现在允许折损夏普门槛大于 1、过拟合概率门槛小于 0。这样的门槛任何证据都满足不了，判定函数会拒绝；注册表检查也应该拒绝，改它要等验收之后。
- 门的内部表格在 Python 里只是"约定上的私有"。现在靠结构测试禁止研究和信号代码去碰；运行时能否再加一道保护（`data/pit.py`，命令行入口会加载），等验收之后再看。

## 代价

- 0017 的规则多了一个例外，要靠一份测试守住边界。测试查的是写在代码里的导入和导入命令行入口时实际加载的模块；如果已有的模块用字符串拼出模块名再导入（`importlib.import_module`），静态检查查不出来，而且只在某个命令运行时才发生的加载，导入入口时也看不到。目前已有的模块里没有这种写法（`importlib` 只用来读包的版本号和数据文件）；审查拉取请求时要留意不要引入。

## 重新考虑的条件

- 如果发现这批模块里有任何一个被录制流程加载了（测试失败），立即停止修改它，按 0017 第 5 条先查 Phase 2。
