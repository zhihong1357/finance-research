# 0014 · 异地备份：找不回的原始数据在 Google Drive 再存一份

**状态：** 已采纳（2026-11-15）。所有者选了 Google Drive。

## 背景

全部数据都在一个 Hugging Face 私有数据集里（决策 0003）。其中大部分丢了还能找回：交易所的历史文件可以按归档清单重新下载，规范层可以由原始层重建（2.5.7）。

但有一部分丢了就永远没了：

- 快照类数据源：Deribit 的盘口摘要、Hyperliquid 的资金费率和持仓量。这些只有当时的状态，没录下就没有。
- 我们在什么时刻看到了什么：纽约联储的利率可以重新下载，但"哪个值在哪个时刻已经能看到"只有录下的原始响应里才有（修订版本表的可用时刻靠它）。

这些东西只有一份，放在一家公司的一个账户里。账户出问题、令牌泄露后被人删改、操作失误，或者这家公司改了免费政策，都会让它们一起消失。行内的做法是至少两份，放在不同的地方。

估计的量：Deribit 每次约 3.1 MB（压缩前），每天 6 次；加上其他几个数据源，压缩后每年 1 到 2 GB。

## 选项

- **(a) Google Drive（采纳）。** 与 Hugging Face 是不同的公司，真正独立；所有者已有 Google 账号和空间。代价：要在 Google Cloud 里建一个应用、拿一个授权令牌（所有者操作一次，约 15 分钟）；应用必须"发布"，否则令牌 7 天就失效。
- **(b) 第二个 Hugging Face 账户。** 最简单，但还是同一家公司，防不住这家公司自己出事。
- **(c) Cloudflare R2。** 独立、10 GB 免费，但开通时要绑信用卡，超出免费额度会扣费，与"只用免费资源"的原则冲突。

## 决定

(a)。做法：

- **备什么。** 数据源目录里 `redownloadable = false` 的数据源（快照类），加上修订版本表用到的数据源（"看到的时刻"不能重新下载）。清单放在配置里。
- **怎么备。** 每天一次，把前一天的原始文件夹 `raw/<数据源>/<年>/<月>/<日>/` 打成一个包，连同包里每个文件的 SHA-256 一起传上去；已经传过的日子不再传。第一次运行把以前的日子全部补上。
- **权限。** 授权只用 `drive.file` 范围：应用只能看到、改到它自己建的文件，碰不到所有者 Drive 里的其他东西。三个值（客户端 ID、客户端密钥、刷新令牌）只放在 GitHub Secrets 里。
- **核对。** 恢复演练：随机取几个备份包，下载、解开，与 Hugging Face 里的文件逐字节比对。
- **监控。** 备份超过两天没有成功，监控开问题，和数据源中断一样。

## 什么情况下重新考虑

备份量超过所有者 Google 空间的一成；Google 改变个人应用的授权规则，令牌无法长期使用；或者以后有了付费预算，可以换成更正式的对象存储。
