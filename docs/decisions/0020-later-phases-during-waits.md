# 0020 · 等待期间提前做后续阶段里不依赖待验收结果的部分

**状态：** 已采纳（2026-11-18）。所有者在会话中决定：在不影响结果的前提下，继续做后续阶段的工作，尽量不闲置。

## 背景

[决策 0017](0017-phase-3-during-phase-2-acceptance.md) 让 Phase 3 在 Phase 2 等待验收时开工。到 2026-11-18，Phase 3 里只用标准库、只新增文件的步骤（3.1a、3.2、3.5、3.6a、3.8、3.9）已全部合并。剩下的步骤要 numpy 或要读数据集，按 0017 都要等 Phase 2 验收（预计 2026-12-04 之后），在那之前开发会闲置。

后续各阶段里，有些部分只是"机器"：用手算的场景和合成数据就能建好、测好，不读真实数据，也不依赖 Phase 3 量出的数字。另一些部分依赖还没出来的结果，提前做会影响结论。

## 决定

**1. 现在可以做的。** 每一步仍然是一个拉取请求、一次只做一步：

| 阶段 | 内容 | 为什么不影响结果 |
|---|---|---|
| Phase 4 | 4.0 开工核实与拆分；信号接口；成本模型（手续费、价差、资金费率、冲击成本）；模拟器的核心（带延迟的成交、保守和压力两种成交情形、逐笔记账、容量估计） | 都是计算规则，用手算场景和合成数据验收；不读真实数据，不用 Phase 3 的数字 |
| Phase 5 | 只写假说卡草稿：机制、对手方、证伪条件、需要的数据、功效估计 | 草稿不跑任何数据，不计入试验，也不冻结阈值 |

**2. 现在不做的，以及原因。**

| 阶段 | 内容 | 原因 |
|---|---|---|
| Phase 4 | 组合模型的权重估计、风险模型、组合构建器、边际贡献检验 | 要 numpy；权重要在探索集上估计；边际贡献检验要用 Phase 3 的工具和量出的误报率 |
| Phase 5 | 任何探索运行、假说注册、确认检验 | 注册时阈值就冻结了，而规程第 5 节的阈值要等 Phase 3 定稿。注册之后检验方案一个字都不能改（工作守则"不改已冻结的检验方案"），所以 Phase 3 定稿的阈值如果更严，现在注册的卡也用不上。探索运行还要等 Phase 4 的模型就位（[决策 0006](0006-single-model.md)：信号的价值是边际贡献） |
| Phase 6 | 目标与约束、基准组合、配置规则 | 能承受的最大回撤由所有者决定（路线图第 6 项）；配置规则要有证据等级 E4 的模型版本才有意义 |
| Phase 7、8 | 模拟盘、实盘闸门 | 要先有通过检验的模型；Phase 8 不在当前范围 |

**3. 约束。** 决策 0017 的五条约束照样适用：不启动 Phase 2 的工作流；只新增文件，不改 `src/`、`config/`、`.github/workflows/` 里已有的文件；不改 `uv.lock` 里已有包的版本；不在 GitHub Actions 上跑读写数据集的任务；Phase 2 任何一项验收没通过时先修 Phase 2。另加三条：

- Phase 4 不能先于 Phase 3 验收：Phase 4 的验收标准要用 Phase 3 量出的误报率。
- Phase 4 的代码不读真实数据，只用手算场景和合成数据测试。
- Phase 5 只写草稿，草稿的状态停在"草稿"，不跑任何运行。

**4. 优先级。** 先 Phase 3 和 Phase 2 验收的事，再 Phase 4，最后 Phase 5 的草稿。Phase 2 验收通过后，Phase 3 剩下的步骤（要 numpy 的）优先于 Phase 4 剩下的步骤。

## 代价

- 同时有两三个阶段在推进。顺序靠上面第 4 条和交接页维持，同一时刻仍只有一个拉取请求在做。
- Phase 4 的模拟器先用标准库写，以后如果性能不够，可能要部分改用 numpy 重写。

## 重新考虑的条件

- 如果 Phase 3 的结果要求改动 Phase 4 已经做好的部分（例如判定方式变了），先改 Phase 4，不绕过。
- 本条在 Phase 2、Phase 3 都验收之后自动失效，届时恢复按路线图逐个阶段推进。
