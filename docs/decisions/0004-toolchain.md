# 0004 · 工具链

**状态：** 已采纳（2026-11-13）。随 Phase 1.1 合并。

## 决定

| 用途 | 选择 | 理由 |
|---|---|---|
| 语言 | Python 3.14 | 科学计算和数据处理的生态最完整。3.12 自 2025 年 4 月起只接受安全修复；3.15 于 2026 年 10 月才发布，生态尚未完全跟上；3.14 处于完整维护期，numpy、pandas、pyarrow、scipy 都已提供对应的安装包 |
| 环境与依赖锁定 | uv | 生成锁定文件，保证每次运行的依赖版本逐一相同 |
| 代码风格 | ruff | 检查和格式化由同一个工具完成。启用的规则包括：不带时区的时间（DTZ）、魔法数字（PLR2004）、类型标注（ANN）、安全（S） |
| 类型检查 | pyright | 在运行之前发现接口用错。`src/` 用严格模式 |
| 测试 | pytest，加 hypothesis 做性质测试 | 事实上的标准；性质测试适合检查不变量，例如"任何查询都拿不到时钟上限之后的数据" |
| 表格数据 | pandas 加 pyarrow | 与现有代码一致 |
| 文件格式 | Parquet | 列式、压缩、带格式信息 |
| 查询 | DuckDB | 直接对 Parquet 文件做查询，不需要常驻的数据库服务 |
| 注册表文件的校验 | pydantic | 用类型定义文件格式，校验和报错都自动生成 |

运行时依赖：

| 包 | 版本 | 加入的步骤 | 理由 |
|---|---|---|---|
| tzdata | 2026.6 | 1.2 | 时区规则随代码锁定，不依赖运行机器的系统时区，保证夏令时换算处处一致 |

pandas、pyarrow、DuckDB、pydantic 在第一次真正用到它们的步骤里加入，不提前安装。

## 原则

- 依赖越少越好。每增加一个依赖，都是一个将来可能出问题的地方。
- 不引入需要常驻服务的组件，因为系统只在 GitHub Actions 上按需运行。
- 不提前引入机器学习框架，等到某个研究项目确实需要时再加。

## 何时重新考虑

某个工具在实际使用中不能满足需要；Python 3.15 的生态成熟之后（预计 2027 年中）评估升级。
